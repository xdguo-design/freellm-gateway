# 自动停用失败路由与控制台联动设计

## 背景与根因

桌面版 EXE 中的阿里云百炼路由向 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` 请求时返回 `401 invalid_api_key`。当前探测失败只记录诊断，不停用路由；真实流量失败只更新内存健康状态，也不会写回数据库，因此坏路由会在重启后再次进入 `auto` 候选。

## 设计

### 1. 认证失败自动停用

当真实请求或手动探测得到 `authentication_error` 时，只停用当前模型路由：`enabled=false`、健康状态为 `disabled`，并通过已有 `Repository.save_route` 持久化。其他同 Provider 路由不受影响。用户更新凭据后手动启用并探测，成功后恢复 `healthy`。

网络错误、超时、5xx 和限流继续使用已有冷却与故障切换策略，不永久停用。

### 2. 模型池与同步目录联动

`/api/admin/catalog/source?scope=models` 在返回目录条目时附加不含敏感信息的池状态：是否精确匹配本地路由、匹配的路由 ID、启用数量和停用数量。匹配优先使用目录 ID/模型名，必要时使用同 Provider 且模型文本包含关系；无法精确匹配的 Provider 只显示 Provider 已配置数量，不误标为已加入。

目录表显示“已在模型池 / 已启用 / 已停用 / 未加入”标记；已匹配条目不再显示重复的“加入模型池”按钮。模型池和 Provider 模型列表也显示目录标记。

### 3. 设置页

设置页改为运行控制台：显示网关、OpenAPI、健康检查、管理 API、聊天和生图地址；显示当前运行统计、Provider 状态、路由状态、API Token 复制按钮和本地数据库/目录导出/sidecar 日志位置。凭据和管理员 Token 不回显。

### 错误处理与安全边界

- 认证失败停用操作必须是幂等的，重复错误不覆盖新凭据。
- 自动停用只作用于单个 route，不删除 Provider、不删除凭据。
- 目录联动字段不包含 `credential_ref` 或任何 Key。
- 复制按钮只复制用户可见的地址、模型名和 API Token。

### 验收标准

- 认证失败后该路由在内存和 SQLite 中均为停用，`auto` 跳过且能使用下一个健康路由。
- 网络错误仍能故障切换，不被永久停用。
- 目录条目能正确标记精确匹配、已停用和未加入状态。
- 设置页显示可执行的连接信息，所有可复制值都有复制按钮。
- Python 测试和 Rust 桌面测试全绿，重建后的 EXE sidecar 健康检查和 `auto` 聊天请求成功。
