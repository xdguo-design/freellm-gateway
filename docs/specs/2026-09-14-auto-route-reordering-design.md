# Auto 路由健康排序设计

## 目标

让 `model=auto` 在真实请求前验证候选路由，并根据真实结果动态调整顺序：失败路由后移，成功路由前移；显式指定模型的请求保持原有语义。

## 行为

- `auto` 请求按当前优先级和能力筛选候选。
- 候选在真实调用前按顺序执行一次轻量预检；预检失败的路由记录健康失败并后移，继续检查下一候选。
- 预检成功后执行真实请求。真实请求成功的路由提升到优先级 1；真实请求失败的路由后移，然后继续故障切换。
- 真实请求结果是最终排序依据；预检成功不保证真实请求参数兼容。
- 显式模型请求不执行自动排序，保留现有故障处理。
- 手动管理页探测继续保持诊断隔离，不因探测失败自动停用或降级路由。
- 排序变化通过现有路由持久化回调保存，重启后仍保持新顺序。

## 实现边界

排序只调整 `priority`，不自动把管理员显式停用的路由重新启用。健康状态、冷却时间和 capability 筛选继续由现有逻辑负责。普通 completion 和 streaming 都采用同一套排序规则。

## 验收标准

1. 健康的低优先级路由不会在高优先级候选仍可用时抢先调用。
2. 预检失败的路由不会执行真实请求，并被移动到末尾。
3. 真实请求返回 `invalid_request` 时，路由被记录为失败并后移，后备路由可以成功响应。
4. 真实请求成功的路由被提升到首位，并通过回调保存全部受影响路由。
5. streaming 与普通 completion 均覆盖以上排序和故障切换行为。
6. 现有健康探测隔离和完整测试集不回归。
